# Переправа

> **Проект учебный и ознакомительный.** Он создан, чтобы разобраться, как устроены протоколы VLESS и Reality, TLS, маршрутизация трафика и администрирование Linux-серверов. Проект ни к чему не призывает, не продвигает и не предлагает услуги VPN или средства обхода ограничений, а программа и сборки публично не распространяются. Автор не отвечает за то, как и где используется код. Если вы используете его, вы сами отвечаете за соблюдение законов своей страны и правил вашего хостинг-провайдера.

Настройка VLESS + Reality на своих VPS: из Windows-приложения или скриптами вручную.

Основная схема — цепочка из двух серверов:

```
клиент → мост (VPS в вашей стране) → выход (VPS за рубежом) → интернет
```

Мост открывает сайты своей страны напрямую (по спискам доменов и адресов geosite и geoip), а остальной трафик отправляет через выходы. Выходы можно добавлять, менять и удалять, а клиентские ссылки при этом остаются прежними. Есть и простой режим: один сервер, к которому клиенты подключаются напрямую. Выход можно открыть и для клиентов: тогда к нему подключаются и напрямую, а мост работает через него как раньше.

## Возможности

- **Роли сервера определяются автоматически.** Приложение проверяет исходящий трафик сервера и подсказывает, годится ли он как мост, как выход или для простого режима. Сервер, которому закрыты зарубежные адреса, может быть только мостом.
- **Подбор SNI.** Поиск подходящих доменов в подсети сервера с проверкой TLS 1.3, HTTP/2, сертификата и DNS; служебные имена, крупные бренды и похожие на VPN-ноды отсеиваются. Свой домен можно проверить вручную.
- **Установка в один шаг.** В том числе на VPS без доступа к GitHub и репозиториям Debian: пакеты ставятся с зеркала Яндекса, а Xray скачивается на компьютере и заливается на сервер.
- **Проверка связи моста с выходом до установки.** Хостер моста может пропускать за рубеж только пинг; приложение заранее предупредит, что такую пару серверов не связать.
- **Пользователи.** У каждого устройства своя ссылка и QR-код и счётчик трафика нарастающим итогом. Добавление, отключение и удаление — без обрыва связи у остальных.
- **Сроки и лимиты.** Доступ до даты и лимит трафика для каждого пользователя. Сервер сам проверяет их каждые 5 минут и отключает вышедших за пределы; ссылка при этом сохраняется и после продления снова работает. Пользователя можно и отключить вручную.
- **Выход и для клиентов.** Одной кнопкой выход становится ещё и сервером для клиентов: у него появляются пользователи, сроки, лимиты и счётчики, а мост продолжает работать через него с прежней ссылкой.
- **Выходы на мосту.** Добавление по ссылке или прямо с другого сервера из списка, проверка связи, автовыбор самого быстрого живого выхода или закрепление за одним. Выходы и сайты напрямую меняются без перезапуска Xray: у подключённых связь не обрывается.
- **Наблюдение.** Пока приложение открыто, оно каждые 15 минут проверяет все серверы: работает ли Xray, доступны ли выходы, жив ли сайт для SNI и не истекает ли его сертификат, хватает ли серверу исходящего трафика для его роли. Состояние видно значком у сервера в списке, проблемы — на странице сервера. В консоли сервера то же самое показывает `exitctl health`.
- **Страна моста и сайты напрямую.** При установке моста выбирается его страна: её доменная зона, адреса (geoip) и готовые списки сайтов (geosite) мост открывает сам, не через выход. Встроенные списки можно посмотреть и исправить в приложении, а сверху добавить свои домены. Для стран, кроме России, Китая и Ирана, нужны полные списки v2fly: их ставит «Обновить списки сайтов».
- **Перенос на другой сервер.** Пользователи переезжают со своими ключами (UUID), с моста на мост — вместе с выходами и сайтами напрямую. Ключи Reality можно перенести, тогда `pbk` и `sid` в ссылках не меняются. Выходу из списка серверов можно одной кнопкой разрешить новый мост.
- **Резервная копия.** Пользователи, ключи Reality, выходы и сайты напрямую сохраняются в файл, зашифрованный паролем (scrypt и AES-256-GCM): его можно восстановить на любом компьютере и любом сервере, даже если исходного сервера уже нет.
- **Обслуживание.** Обновление Xray и списков сайтов с компьютера (подходит и серверам без доступа к GitHub): приложение показывает версию Xray на сервере и последнюю доступную, а обрыв связи во время обновления не мешает ему закончиться, если компьютер ходит на сервер через этот же Xray. Последние Xray и списки сохраняются на компьютере и идут в ход, когда GitHub не отвечает; если GitHub недоступен совсем, их можно выбрать из файлов, скачанных любым способом (с проверкой по `.dgst` и `.sha256sum`, если они лежат рядом). Обновление `exitctl` на сервере, полное снятие установки.
- **Приватность.** Журнал посещённых сайтов на сервере выключен. Доступы к серверам хранятся только на этом компьютере, пароли зашифрованы ключом учётной записи Windows (DPAPI). Ключ сервера подтверждается при первом подключении, а при его смене подключение останавливается.

## Состав

| Файл | Где запускается | Назначение |
| --- | --- | --- |
| `bridge-setup.sh` | мост, от root, `exitctl` рядом | `COUNTRY=ru bash bridge-setup.sh SNI` — мост: сайты своей страны напрямую, остальное через выходы |
| `exit-setup.sh` | выход, от root | `bash exit-setup.sh IP_МОСТА SNI` — выход, порт 443 открыт только для моста |
| `simple-setup.sh` | один сервер, от root, `exitctl` рядом | `bash simple-setup.sh SNI` — простой режим |
| `prepare-restricted.sh` | сервер с ограниченным исходящим трафиком | переключает apt на зеркало, ставит Xray из переданной папки |
| `update-geodata.sh` | мост или простой сервер | ставит новые списки сайтов, при ошибке возвращает старые |
| `update-xray.sh` | любой сервер с этой установкой | ставит Xray из переданной папки; если новая версия не принимает конфиг или не запускается, возвращает старую |
| `uninstall.sh` | любой сервер с этой установкой | удаляет Xray, настройки и правила файрвола для 443 |
| `exitctl` | мост или простой сервер (python3 ≥ 3.9, без зависимостей) | выходы, пользователи, сроки и лимиты, подбор SNI, состояние и наблюдение, проверка связи, открытие выхода для клиентов |
| `app/` | Windows | приложение на Go и Wails |

Порт SSH для файрвола задаётся переменной `SSH_PORT` (по умолчанию 22).

## Приложение

Требуется Windows 10/11 с WebView2 (в Windows 11 есть сразу). Готовый файл после сборки — `app/build/bin/pereprava.exe`.

1. «Добавить сервер»: адрес, порт SSH, пользователь, пароль или SSH-ключ. Если вход не под root, нужен sudo.
2. Подтвердить ключ сервера при первом подключении.
3. Выбрать роль, подобрать или проверить SNI, нажать «Установить».
4. Добавить пользователей и отправить им ссылку или QR-код. Клиенты: v2rayN, Hiddify, Happ (Windows); v2rayNG, v2RayTun, Happ, Hiddify (Android).
5. Для цепочки: поставить выход, указав мост из списка, и добавить его на мосту через «Взять ссылку с сервера».

Серверные скрипты вшиты в приложение: при подключении оно заливает их во временную папку на сервере и вызывает `exitctl` с `--json`.

## Ручная установка скриптами

```bash
# на выходе
bash exit-setup.sh IP_МОСТА домен-для-sni.example
# на мосту (exitctl лежит рядом)
bash bridge-setup.sh домен-для-sni.example
exitctl add 'vless://...ссылка с выхода...' nl1
exitctl user add phone
```

`exitctl --help` выводит все команды. Ссылки и ключи сохраняются на серверах в `/root/*-info.txt`.

## Разработка

Нужны Go, Wails v2 и Node.js. Команды выполняются в `app/`:

```bash
go generate ./internal/bundle   # после правки скриптов в корне: обновить вшитые копии
go test ./... -count=1
wails build -clean
```

Тесты серверных скриптов не трогают серверы и сеть: Xray заменён заглушками, скан SNI идёт по локальным TLS-серверам (нужен `openssl`). Запуск из корня репозитория:

```bash
python3 tests/run_all.py
```

Они и тесты Go запускаются на GitHub при каждом пуше (`.github/workflows/tests.yml`): скрипты — на Linux с Python 3.9 и 3.12, приложение — на Windows.

Источник серверных скриптов — корень репозитория; `app/internal/bundle/files/` только копия, её актуальность проверяет `bundle_test.go`. Скрипты выполняются на Linux, поэтому строки только LF (следит `.gitattributes`).
