# Переправа

Настройка VLESS + Reality на своих VPS: из Windows-приложения или скриптами вручную.

Основная схема — цепочка из двух серверов:

```
клиент → мост (VPS в России) → выход (VPS за рубежом) → интернет
```

Мост открывает российские сайты напрямую, а остальной трафик отправляет через выходы. Выходы можно добавлять, менять и удалять, а клиентские ссылки при этом остаются прежними. Есть и простой режим: один сервер, к которому клиенты подключаются напрямую.

## Возможности

- **Роли сервера определяются автоматически.** Приложение проверяет исходящий трафик сервера и подсказывает, годится ли он как мост, как выход или для простого режима. Сервер, которому закрыты зарубежные адреса, может быть только мостом.
- **Подбор SNI.** Поиск подходящих доменов в подсети сервера с проверкой TLS 1.3, HTTP/2, сертификата и DNS; служебные имена, крупные бренды и похожие на VPN-ноды отсеиваются. Свой домен можно проверить вручную.
- **Установка в один шаг.** В том числе на VPS без доступа к GitHub и репозиториям Debian: пакеты ставятся с зеркала Яндекса, а Xray скачивается на компьютере и заливается на сервер.
- **Проверка связи моста с выходом до установки.** Хостер моста может пропускать за рубеж только пинг; приложение заранее предупредит, что такую пару серверов не связать.
- **Пользователи.** У каждого устройства своя ссылка и QR-код, счётчики трафика. Добавление и удаление — без обрыва связи у остальных.
- **Выходы на мосту.** Добавление по ссылке или прямо с другого сервера из списка, проверка связи, автовыбор самого быстрого живого выхода или закрепление за одним.
- **Сайты напрямую.** Свои домены, которые мост открывает сам, не через выход.
- **Обслуживание.** Обновление Xray и списков российских сайтов с компьютера (подходит и серверам без доступа к GitHub), обновление `exitctl` на сервере, полное снятие установки.
- **Приватность.** Журнал посещённых сайтов на сервере выключен. Доступы к серверам хранятся только на этом компьютере, пароли зашифрованы ключом учётной записи Windows (DPAPI). Ключ сервера подтверждается при первом подключении, а при его смене подключение останавливается.

## Состав

| Файл | Где запускается | Назначение |
| --- | --- | --- |
| `bridge-setup.sh` | мост, от root, `exitctl` рядом | `bash bridge-setup.sh SNI` — мост: российские сайты напрямую, остальное через выходы |
| `exit-setup.sh` | выход, от root | `bash exit-setup.sh IP_МОСТА SNI` — выход, порт 443 открыт только для моста |
| `simple-setup.sh` | один сервер, от root, `exitctl` рядом | `bash simple-setup.sh SNI` — простой режим |
| `prepare-restricted.sh` | сервер с ограниченным исходящим трафиком | переключает apt на зеркало, ставит Xray из переданной папки |
| `update-geodata.sh` | мост или простой сервер | ставит новые списки сайтов, при ошибке возвращает старые |
| `update-xray.sh` | любой сервер с этой установкой | ставит Xray из переданной папки; если новая версия не принимает конфиг или не запускается, возвращает старую |
| `uninstall.sh` | любой сервер с этой установкой | удаляет Xray, настройки и правила файрвола для 443 |
| `exitctl` | мост или простой сервер (python3 ≥ 3.9, без зависимостей) | выходы, пользователи, подбор SNI, состояние сервера, проверка связи |
| `app/` | Windows | приложение на Go и Wails |

Порт SSH для файрвола задаётся переменной `SSH_PORT` (по умолчанию 22).

## Приложение

Требуется Windows 10/11 с WebView2 (в Windows 11 есть сразу). Готовый файл после сборки — `app/build/bin/pereprava.exe`.

1. «Добавить сервер»: адрес, порт SSH, пользователь, пароль или SSH-ключ. Если вход не под root, нужен sudo.
2. Подтвердить ключ сервера при первом подключении.
3. Выбрать роль, подобрать или проверить SNI, нажать «Установить».
4. Добавить пользователей и отправить им ссылку или QR-код. Клиенты: v2rayN, Hiddify, Happ (Windows); v2rayNG, v2RayTun, Happ, Hiddify (Android).
5. Для цепочки: поставить выход, указав мост из списка, и добавить его на мосту через «Взять ссылку с сервера».

Серверные скрипты вшиты в приложение: при подключении оно заливает их во временную папку на сервере и вызывает `exitctl` с `--json`.

## Ручная установка скриптами

```bash
# на выходе
bash exit-setup.sh IP_МОСТА домен-для-sni.example
# на мосту (exitctl лежит рядом)
bash bridge-setup.sh домен-для-sni.example
exitctl add 'vless://...ссылка с выхода...' nl1
exitctl user add phone
```

`exitctl --help` выводит все команды. Ссылки и ключи сохраняются на серверах в `/root/*-info.txt`.

## Разработка

Нужны Go, Wails v2 и Node.js. Команды выполняются в `app/`:

```bash
go generate ./internal/bundle   # после правки скриптов в корне: обновить вшитые копии
go test ./... -count=1
wails build -clean
```

Источник серверных скриптов — корень репозитория; `app/internal/bundle/files/` только копия, её актуальность проверяет `bundle_test.go`. Скрипты выполняются на Linux, поэтому строки только LF (следит `.gitattributes`).
