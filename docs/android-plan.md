# План: Android-приложение «Переправа»

> Проект учебный и ознакомительный (см. README). Документ описывает, как десктопное
> приложение-админка превращается в схему «сервер — источник правды, телефон — тонкий клиент»
> с двумя режимами: пользовательским и администратора.

## Целевая картина

- **Пользовательский режим.** Установил приложение → отсканировал QR (или открыл файл/ссылку)
  от администратора → большая кнопка «Подключиться». Всё остальное приехало в профиле:
  ссылка, лимиты, разрешённые варианты. Пользователь может только:
  - выбрать точку подключения (если администратор разрешил несколько: через мост / напрямую
    через выход, разные страны);
  - включить «сайты моей страны напрямую» (клиентская маршрутизация);
  - выбрать приложения, которые идут через туннель (per-app VPN).
- **Режим администратора.** Те же серверы, пользователи, лимиты, выходы, наблюдение —
  что в десктопном приложении, но с телефона. За PIN/биометрией.
- **Сервер раздаёт актуальные конфигурации.** Профиль — не одноразовая ссылка, а документ,
  который приложение периодически обновляет с сервера (подписка). Смена SNI, перенос,
  новые точки подключения доезжают сами.

## Архитектура

```
┌─ Android APK ────────────────────────────────┐
│ Kotlin + Jetpack Compose (UI, два режима)    │
│ pereprava-core.aar (Go, gomobile):           │
│   internal/client — конфиг Xray из ссылки    │
│   internal/remote — SSH для админ-режима     │
│   профиль/подписка — разбор, кэш             │
│ VpnService → tun2socks → Xray in-process     │
└──────────────────────────────────────────────┘
        │ VLESS+Reality            │ HTTPS (подписка)      │ SSH (админ)
┌───────┴──────────────────────────┴───────────────────────┴──────────┐
│ Сервер: Xray + exitctl (sub export / sub enable …)                  │
└─────────────────────────────────────────────────────────────────────┘
```

Переиспользуется почти весь Go-код: `internal/client` (ParseLink, Config, CountryRules),
`internal/remote` (чистый Go + x/crypto/ssh). Ядро экспортируется одной точкой входа
`CoreCall(method, jsonArgs) → jsonResult` — зеркало Wails-биндингов десктопа.

## Формат профиля (v1)

```json
{
  "version": 1,
  "updated": "2026-11-15T21:00:00Z",
  "user": {"name": "phone", "expires": 1767225599, "limitBytes": 107374182400, "usedBytes": 12884901888},
  "endpoints": [
    {"id": "bridge-203.0.113.9", "kind": "bridge", "country": "ru", "link": "vless://…", "default": true,
     "subscription": {"url": "https://203.0.113.9:8443/s/<токен>", "certSha256": "ab12…"}},
    {"id": "direct-198.51.100.7", "kind": "direct", "country": null, "link": "vless://…", "default": false}
  ],
  "policy": {"allowBridge": true, "allowDirect": true}
}
```

- `kind`: `bridge` — трафик идёт цепочкой через выходы; `direct` — простой сервер или выход,
  открытый для клиентов.
- `country` у bridge — страна моста (её сайты уже идут напрямую на сервере, клиенту ничего
  включать не нужно).
- `policy` пересчитывается по списку endpoint'ов при объединении профилей с нескольких серверов.
- Передача: QR/ссылка `pereprava://profile#<base64url(JSON)>` или файл `*.pereprava-profile`
  с тем же JSON.

## Каналы обновления профиля

| Вариант | Статус | Суть |
| --- | --- | --- |
| A. Файл/QR | **Этап 1 (сделан первым)** | Администратор экспортирует профиль из десктопного приложения |
| B. HTTPS-подписка | **Этап 3 (сделано)** | `exitctl sub enable --port 8443`: отдельный порт, токен на пользователя, ETag; TLS self-signed с пиннингом fingerprint при импорте (TOFU, как SSH-ключи). Тот же URL с `?format=v2ray` отдаёт классическую base64-подписку для v2rayNG/Happ/Hiddify |
| C. Через SSH | запасной | Служебный пользователь с forced-command `exitctl sub get` в authorized_keys; ни одного нового порта |

На порту 443 рядом с Reality настоящий HTTPS не поднять, не ломая маскировку, — только
отдельный порт/IP или SSH.

## Этапы

### Этап 1. Формат профиля + экспорт (релиз 0.9.0) — этот PR
- `exitctl sub export <имя> [--host АДРЕС] [--json]` — профиль пользователя одного сервера.
- Страна моста сохраняется в `pereprava.state` при установке и при `direct country`;
  для старых установок определяется по встроенным спискам «напрямую».
- Десктоп: кнопка «Профиль» у пользователя — диалог с QR, deep-link, сохранением файла;
  можно отметить другие серверы, где есть такой же логин, — endpoints объединяются.

### Этап 2. Android MVP — пользовательский режим (3–6 недель)
- Kotlin + Compose, minSdk 26; gomobile-сборка ядра; Xray-core как библиотека (AAR)
  + tun2socks к SOCKS на 127.0.0.1 (конфиг строит тот же `internal/client.Config`).
- Импорт: QR (CameraX + ML Kit), deep-link, файл, буфер обмена; несколько профилей.
- VpnService: foreground-уведомление, переподключение при смене сети, per-app VPN,
  инструкция для always-on.
- Выбор endpoint'а в рамках `policy`; «сайты моей страны напрямую» (геоданные в assets).
- Секреты в Android Keystore; экран журнала с «поделиться».

### Этап 3. Подписка (сделано в этом PR)
- `exitctl sub enable [--port N]` (по умолчанию 8443): HTTPS-раздача профилей на отдельном
  порту (Reality-маскировка не затрагивается), служба `pereprava-sub` (systemd), self-signed
  сертификат, его sha256-отпечаток приложение пиннит при импорте (TOFU, как SSH-ключи).
- Токен на пользователя (`sub token|rotate|revoke`), хранится в `exitctl-sub.json` с правами
  0600 — тот же уровень секретности, что у UUID и ключей Reality рядом. Отключение раздачи
  токены сохраняет (как `exit close` — пользователей).
- Ответ раздачи: профиль JSON с ETag/304; `?format=v2ray` — классическая base64-подписка
  для v2rayNG/Happ/Hiddify. Журнала запросов нет; простой лимит запросов с адреса.
- Десктоп: панель «Раздача профилей» на странице сервера; «Профиль» пользователя вкладывает
  ссылку подписки автоматически; перевыпуск токена — там же.
- Android (этап 2): опрос при запуске + ежедневный WorkManager + вручную; бесшовное применение
  (смена SNI не рвёт старые ссылки благодаря keepOld).

### Этап 4. Admin-lite на Android (2–4 недели)
- Серверы + значки health (WorkManager, 15 минут — как на десктопе); TOFU ключей хоста.
- Добавление сервера: ключ ed25519 генерируется в Keystore (неэкспортируемый), pubkey
  ставится по одноразовому паролю.
- Пользователи: добавить/отключить/лимиты/сброс трафика, отправить профиль/QR подписки.
- Выходы: список, проверка, закрепить/авто. Раздача: включить/выключить, ротация токенов.

### Этап 5. Полная админка на Android (4–8 недель, опционально)
- Установка ролей, подбор/смена SNI, обновления Xray/геоданных, резервные копии, миграция,
  списки «напрямую». Логика detached-заданий портируется в ядро без изменений.

### Этап 6. Сборка и релизы
- CI: gomobile-AAR (NDK), APK, подпись ключом из GitHub Secrets, артефакт
  `pereprava-*-android.apk` в релизе рядом с exe/tar.gz; совместимость с Obtainium.

## Осознанно не входит (не «малой кровью»)

- Push актуальных конфигов (FCM) — достаточно опроса.
- iOS — отдельный проект (Network Extension, entitlements, App Store).
- Google Play: декларации для VPN-приложений; сначала APK напрямую.
- «Системный прокси» как на Windows — на Android его не существует (VpnService или per-app).
- Обновление движка Xray с GitHub на телефоне — движок зашит в APK и обновляется с ним.
- Каталог нескольких мостов с автовыбором страны — в v1 «страна» = выбор endpoint'а профиля.

## Безопасность

- Ссылки и токены — секреты: Keystore на телефоне; на сервере токены в `exitctl-sub.json` с правами 0600 — тот же уровень, что у UUID и ключей Reality в конфиге рядом.
- Подписка только по HTTPS; self-signed — с пиннингом fingerprint, показанным администратором.
- Админ-режим за биометрией/PIN; SSH-ключи телефона неэкспортируемые.
- Журналы посещённых сайтов не ведутся — как и на сервере.
